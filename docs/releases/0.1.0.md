# iLibrary: v0.1.0, Catalog-Driven Music Libraries for Apple Music on macOS

The first packaged preview of iLibrary, a macOS command that prepares music through a JSON catalog and adds albums to a local Apple Music library in a controlled order.

> [!IMPORTANT]
> Version 0.1.0 is experimental. Use selected copies and complete the separate-user validation before operating a personal library. Cloud matching is not prevented, and real Trash behavior, notarization, and execution across every supported macOS release remain unverified. iLibrary is independent software with no affiliation with Apple. Use recordings and artwork that you have the right to process, and review catalogs and reports before sharing them.

## Highlights

- **Catalog Workflow.** `export`, `prompt`, `schema`, and `validate` prepare and check a catalog; `apply` writes its tags, names, and release dates, and `timestamps` can set existing file and folder dates independently.
- **Verified Import.** `import` converts FLAC, WAV, and AIFF to Apple Lossless with decoded PCM verification, or copies M4A without re-encoding and removes purchase metadata. Integer mono and stereo audio are supported; encrypted audio is refused.
- **Ordered Music Addition.** `add` moves selected albums into Music's media folder, confirms each album, and retains a resumption journal. `check` compares files and library state, and `doctor` reports environment problems. Mutating commands provide a dry run, state their plans, and verify their results; batches can remain partially complete after failure.
- **Packages.** Homebrew, npm, and PyPI distributions support macOS 14 or later on Apple silicon. All three public installation paths passed version, schema, and help checks; npm and PyPI retained the reviewed executable bytes.

Verification passed 154 synthetic Swift tests, strict formatting, and eight publication-guard tests. The maintainer reported twelve successful Music command checks in a separate macOS user. Qualification on copies of 301 files in 20 folders passed catalog export, application, arrangement, repeated application, and file diagnostics; originals retained their bytes and dates. These measurements do not establish cloud behavior or compatibility with every macOS release. See the [publication report](https://github.com/x96x64/ilibrary/blob/34bf8ed35e28f2e63552cb90c706529a60220353/docs/reports/release-publication.md) for release identity and verification evidence.

## Installing and Upgrading

Install with `brew install x96x64/tap/ilibrary`, `npm install -g @x96_64/ilibrary@0.1.0`, or `python -m pip install x96_64-ilibrary==0.1.0` in a Python virtual environment. Update through the same channel with `brew upgrade ilibrary`, `npm install -g @x96_64/ilibrary@latest`, or `python -m pip install --upgrade x96_64-ilibrary` in that environment.

Homebrew builds from source and requires Swift 6 from Xcode or the Command Line Tools. npm and PyPI install a prebuilt native executable without a Swift toolchain. The executable is signed ad hoc; Developer ID signing and notarization are not provided. Keep backups, catalogs, and resumption journals, and follow [Test Library Validation](https://github.com/x96x64/ilibrary/blob/main/docs/test-library-validation.md) before personal-library use.
