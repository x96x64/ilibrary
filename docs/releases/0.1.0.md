# iLibrary: v0.1.0, Catalog-Driven Music Libraries for Apple Music on macOS

## Experimental Release

iLibrary 0.1.0 prepares music files through a JSON catalog and adds albums to a local Apple Music library in a controlled order. Use selected copies and a separate test library before adopting a workflow. iLibrary is not affiliated with Apple.

## Included Commands

- `import` converts FLAC, WAV, and AIFF to Apple Lossless with PCM verification, or copies M4A files without re-encoding and removes purchase metadata.
- `export`, `prompt`, and `schema` prepare catalogs for manual or AI-assisted completion.
- `validate` and `apply` check correspondence and apply tags, names, and release dates.
- `timestamps` changes existing file and folder dates without creating missing paths.
- `add` moves selected files into Music's media folder, adds and confirms one album at a time, and resumes through a journal.
- `check` and `doctor` report file, library, and environment problems.

Every mutating command provides a dry run, lists planned changes, and verifies its writes. Batches are not transactions, and earlier completed operations can remain after a later failure.

## Installation

Requires macOS 14 or later on Apple silicon. Choose one channel:

```bash
brew install x96x64/tap/ilibrary
# Or:
npm install -g @x96x64/ilibrary@0.1.0
# Or, inside a Python virtual environment:
python -m pip install x96x64-ilibrary==0.1.0
```

Homebrew builds from source and requires Swift 6. npm and PyPI install the same native binary; JavaScript and Python are not runtime dependencies of the command. The release assets include binary and source archives, the formula, build identity, and checksums. See [Distribution](https://github.com/x96x64/ilibrary/blob/main/docs/distribution.md) for installation and verification details.

## Verification

The public suite uses original synthetic data. The implemented Music commands passed twelve checks reported by the maintainer in a separate macOS user. Qualification on copies of 301 files in 20 folders passed catalog export, identity application, arrangement, repeated application, and file diagnostics; originals retained their bytes and dates. The [engineering reports](https://github.com/x96x64/ilibrary/blob/main/docs/README.md) distinguish these measurements from inference and unverified behavior.

## Known Limits

Cloud matching is not prevented or measured. Conversion supports integer mono and stereo PCM; protected audio is refused. Real Trash operations, Developer ID signing, notarization, and compatibility across every supported OS version remain unverified. Music comparisons cover the fields exposed by the adapter, not every library property. Back up files and retain addition journals for recovery.
