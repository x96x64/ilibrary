# M11 Date Correction and Version 2 Qualification Preparation

## Purpose and Status

This report records the correction of the defect that stopped the first M11 qualification run, described in [M11 Qualification Results, First Run](m11-qualification-results.md), and the preparation of the replacement procedure and bundle under the maintainer's authorization of October 20, 2026. M11 has not passed: the corrected reader has not been executed against Music, and every gate that the first run did not reach remains unmeasured. Findings are classified as measured, inferred, or unknown.

## Correction of the Date Conversion

Commit `45489b7` changes the bulk snapshot script in `Sources/LibraryMac/MusicBulk.swift`. For each date added, the script still computes the difference `x` from local 2000-01-01 00:00:00, but it no longer coerces `x` to text. It emits the whole days `x div 86400` and the remainder `(x - d * 86400) as integer` as two plain integers separated by one space. The new `MusicApp.dateOffset` accepts exactly two parts, each an optional minus sign followed by ASCII digits, requires the remainder to lie between -86400 and 86400, recombines `d * 86400 + r` with overflow-checked arithmetic, and refuses magnitudes above 400,000,000,000 seconds, beyond the span of AppleScript dates (inferred bound). Refusals use the existing `MusicAppError.unexpectedResult`. The base, the local-time interpretation, `unixSeconds`, the section layout, and every other property are unchanged.

The implementation was delegated to a subagent under a written scope and verification brief and reviewed by the coordinating agent before acceptance. The delegated report did not follow the prescribed response format; its claims were therefore verified independently rather than accepted as stated.

The following were measured with `osascript` on constructed dates, without referencing any application. The revised loop produced `6213 67711`, `6213 67712`, `9789 41600`, `9789 45296`, `13888 76800`, `0 -1`, `-1 -1`, `-11574 -6400`, and `0 0` for offsets 536,870,911; 536,870,912; 845,811,200; 845,814,896; 1,200,000,000; -1; -86,401; -1,000,000,000; and 0, each of which recombines exactly. For the current date it produced `9789 42330`, which recombines to 845,811,930 seconds, the offset that Python computed independently at the same moment. The delegated checks found that `div` truncates toward zero, that the remainder carries the sign of the difference, and that remainders of fractional differences round as the former whole-difference coercion did (for example `1.5`, `2.5`, `-2.5`, and `86399.5` gave identical results by both methods).

Two semantic properties are preserved and not newly examined. Rounding of fractional seconds follows AppleScript's `as integer`, as before. Whether AppleScript's date subtraction counts elapsed seconds or local wall-clock seconds across a daylight-saving transition is unknown; the existing conversion assumes elapsed seconds, the correction does not change that assumption, and a time zone without daylight-saving time, such as the one recorded in the first run, is not affected by it (inferred).

## Regression Tests and Probe Report

`Tests/LibraryMacTests/MusicBulkTests.swift` adds six tests: the generated script never coerces the full difference to text; a present-day offset (2026-10-20T12:34:56Z) recombines to the exact second; the AppleScript integer boundary at 536,870,911 and 536,870,912 recombines exactly; negative offsets before 2000 recombine exactly; remainders rounded to a full day recombine correctly; and 31 malformed items, including the exponent text `8.458112E+8`, decimal text, missing or extra parts, irregular whitespace, signs, out-of-range remainders, overflow, and non-ASCII digits, are refused through both the item parser and the snapshot parser. The existing snapshot tests were rewritten to the new encoding.

Commit `9fd80f0` extends the read-only probe so that its report, now format `ilibrary-m11-readers-report-2`, records the smallest and largest age of the snapshot's dates added relative to the probe's clock and the number of distinct values. The first run could show only whether every track had a date added. The ages reveal no identity; for tracks added minutes before the probe, plausible values are small and positive. Two probe tests cover the computation and its omission without a reference time.

At `e842f45`, which has the same sources as the bundle commit, all Swift tests passed (130 command, 105 `RebuildCore`, 24, 13 `M11Probe`, 37 `LibraryMac`, 8, 5, and 41 tests in the remaining runs), `swift format lint --strict --recursive Sources Tests Package.swift scripts` reported nothing, and the 11 collection tests passed (measured). Intermittent failures to load the `TestingMacros` plugin were reported by the delegated agent in some runs; the coordinating agent's runs did not encounter them, and their cause is unknown.
