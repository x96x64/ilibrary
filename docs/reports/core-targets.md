# Core Targets

## Status

Historical record, October 16, 2026. This report records milestone M2: the Foundation-only targets `MP4Core`, `FLACCore`, and `CatalogCore`, their synthetic tests, continuous integration on macOS and Linux, and a validation against copies of the private references. Findings are classified as measured, inferred, or unknown, as in the [Architecture Spike](architecture-spike.md). The maintainer's media folder and Music library were not touched.

## Implemented Decisions

| Decision | Implementation |
| --- | --- |
| 5. Rebuild `moov`; refuse offsets beyond 32 bits | `MP4File.writePlan` rebuilds the movie box, copies every other top-level box from the source, and maps chunk offsets through the original layout. A 32-bit table whose relocated offset would exceed 32 bits raises `chunkOffsetsExceed32Bits`; `co64` tables are read and relocated. |
| 6. `FLACCore` as a separate target | `FLACMetadata` reads STREAMINFO, Vorbis comments, and pictures, skips a leading ID3v2 tag, and rejects truncated or malformed blocks. |
| 7. Verification of stream copies | `MP4File.streamDifferences` compares media-data payloads, sample tables (`stts`, `stsc`, `stsz`, `stz2`, `ctts`, `stss`, `elst`, `mdhd`), and chunk positions relative to their media data. `MP4Writer` refuses to replace a file when any difference remains. PCM verification of conversions belongs to the planned `ConversionMac`. |
| 8. Free space | Not applicable to the Core targets; it belongs to `ConversionMac`. |
| 9. Timestamps | `ReleaseDate.localStart(in:)` computes the first instant of a date and reports whether it is midnight. File operations belong to the planned `LibraryMac`. |
| 10. Purchase metadata | `removePurchaseMetadata` removes the twelve purchase atoms, including `xid `, keeps only allowlisted sample-entry children, zeroes all padding, and keeps `iTunSMPB` and `stik`. |

The maintainer specified on October 16, 2026, that only encrypted audio is refused: sample entries of type `drms` and `.m4p` files. Purchaser information in files that are not encrypted, including a `pinf` box with the `itun` scheme or a `sinf` box inside an `mp4a` entry, is removed rather than refused. The implementation also refuses `enca`, the ISO Common Encryption audio entry, because it likewise denotes encrypted audio; this extension is recorded here for the maintainer's review.

## Synthetic Tests

The public suite uses Swift Testing and only data generated by the tests. Measured on the maintainer's Mac (macOS 27.0.1, Swift 6.4 from the Command Line Tools) on October 16, 2026, all 72 tests passed: 24 in `MP4CoreTests`, 8 in `FLACCoreTests`, and 40 in `CatalogCoreTests`. The release build and `swift format lint --strict` over `Sources`, `Tests`, `Package.swift`, and `scripts` reported no problem.

- **MP4Core.** Synthetic files are built with consistent sample tables and patterned chunk data in both layouts. Tests cover byte-identical reproduction of unchanged files, relocation with the movie box first, unchanged offsets with it last, absorption into item-list and top-level padding, fallback to relocation, `co64` tables, the 32-bit limit, idempotence, in-place replacement, item-list creation, value widths, truncated and unrelated input, a failed rewrite that leaves the destination and directory unchanged, removal of purchase metadata from a file with the structure observed in M1, and refusal of `drms`, `enca`, and `.m4p`.
- **FLACCore.** Synthetic metadata covers the ranges of the STREAMINFO fields, including a 36-bit frame count, comments in order with case-insensitive lookup, pictures, other blocks, the audio offset, an ID3v2 prefix, and truncated or malformed blocks.
- **CatalogCore.** Tests cover the example of the planning study, round-trip encoding, rejection of other documents and format versions, located diagnostics for unknown fields, types, required values, invalid dates, and duplicate albums, warnings for `(P)` and empty catalogs, equality of the published and embedded JSON Schema and of the schema's fields with the validator's, dates and time zones including a skipped midnight, title rules, the live-designation review, matching, naming, the four orders, and the resolution of album and track values.

## Private Reference Validation

`scripts/reference_validation/validate-private.sh` processed copies of the twelve private references inside `reference-private/work/`, printed no metadata value, and removed the copies afterwards. Every original was byte-identical to its copy after processing (measured).

- **Purchased file (measured).** The copy was processed, not refused. Ten purchase atoms and seven sample-entry boxes (`dmix`, `udi2`, `udc2`, `udex`, `sbtd`, `pinf`, and `free`) were removed. The 33,273 bytes removed from the movie box were absorbed into the padding after the item list, so the movie box kept its size of 113,859 bytes and no chunk offset changed. The purchaser's account and owner strings occurred zero times in the output, the stream comparison found no difference, and FFmpeg decoded identical PCM.
- **Other MP4 files (measured).** The copy cleaned during manual curation and the nine Apple Lossless files were processed without change by the purchase-metadata removal, and their stream comparison and FFmpeg PCM were identical. Retitling each file left the stream identical; the cleaned copy needed relocation of 14 chunk offsets, and every other file absorbed the change into padding.
- **FLAC file (measured).** The stream information was read as 176,400 Hz, two channels, 24 bits, and 51,826,701 frames, in agreement with the spike. The file holds 22 comments, including 9 whose field names are not common Vorbis fields, and one 2,447,628-byte JPEG front cover. What those fields contain is unknown; whether they identify the purchase must be examined before tags are carried into converted files in M4.

## Continuous Integration

`.github/workflows/ci.yml` builds the release products, checks formatting, and runs all tests on `macos-latest`, and runs the tests of the Core targets in the official `swift:6.4-noble` image on Ubuntu 24.04, with time-zone data installed for the date tests. The image tag was confirmed on Docker Hub on October 16, 2026. Neither job has run yet, because the repository has not been pushed; behavior on Linux, in particular of Foundation's string folding and time-zone rules, is unknown until then.
