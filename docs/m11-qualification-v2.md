# M11 Backup and Inventory Qualification, Version 2

## Purpose and Status

This procedure qualifies the parts of milestone M11 that only a maintainer-operated run can establish. The portable logic of M11 (the strict export, the file inventory, plan validation, the recovery record, and the date policies) is verified by the test suite. This run measures five matters that the suite cannot: the live equivalence of the bulk Music reader and the per-track reader, the cloud status values that Music reports for local files in a new library, whether a Finder copy to an external drive preserves the dates that `ilibrary rebuild prepare` compares, the device-independence signals that macOS reports for a real external drive, and the wait for the maintainer to eject the backup volume.

The first run, made with the [first procedure](m11-qualification.md), stopped at Step 6 because the bulk snapshot reader could not convert the dates added of recently added tracks; see [M11 Qualification Results, First Run](reports/m11-qualification-results.md). Version 2 uses a bundle built from the corrected source. Its steps and expected results are those of the first procedure, with new names for every library, folder, and report, explicit stop rules for the reader probe, and precautions for a backup drive that also holds Time Machine backups.

Nothing in this document is a result. M11 has not passed until the report produced by Step 12 has been assessed. A successful run shows only what the report records, for this Mac, this drive, and this synthetic library. It does not describe a personal library, other drives, or other versions of macOS or Music.

## Scope and Stop Boundaries

The run uses synthetic files only: 12 original tracks (3 albums by 2 artists, 4 tracks each, with distinct release dates) generated by the preparation script. It is performed in the existing separate test user, which has no Apple Account and no synchronization. The user name must begin with `ilibrarytest` or `ilibrary-test`, because the probe refuses any other user.

The run never touches the personal library, the personal Music folders, or any personal drive contents. It does not use any library from M10 or from the first M11 run. The first run's library `M11-qualification`, its folder `~/ilibrary-m11-qualification` with its `results`, the archive `/Users/Shared/ilibrary-m11-qualification.zip`, and the report `/Users/Shared/ilibrary-m11-qualification-report.txt` are evidence: do not open, reuse, rename, empty, move, or delete any of them. Apart from the addition of the synthetic albums by `ilibrary add` in Step 5, the run does not move, rename, or edit anything in Music, and it removes no registration, manually or by command. It never erases, formats, or partitions a drive, and it never asks the maintainer to do so.

Stop at once, change nothing further, and report the last output when any of the following occurs: the user is not the test user; an Apple Account is signed in; a command refuses or fails in a way that this document does not list as expected; the probe of Step 6 reports an error; a folder that this document creates already exists; Music asks anything other than the Automation permission; the Finder asks for a password or refuses to create or copy a folder on the drive; or no suitable external drive is available. After a stop, Step 12 still produces the report.

## What the Maintainer Must Provide

The run needs a new folder on an external drive that is formatted as APFS or HFS+ (Mac OS Extended, including its case-sensitive and journaled variants). Other formats, such as exFAT or FAT, are refused by `rebuild prepare` and are not a valid choice. The drive must be a real, separate physical device: a partition of the internal disk, a disk image, and a network volume do not qualify. The procedure creates exactly one new folder, `M11-v2-backup`, at the root of the drive, and copies the synthetic `Music` folder into it with the Finder. iLibrary reads only that folder and the volume's properties; it writes nothing to the drive and deletes nothing on it. Merely connecting a drive and opening it in the Finder can let macOS update its own hidden metadata on the volume; that is independent of this procedure.

If no suitable drive is available, or if the only available drive has another format, stop. Do not erase, reformat, repartition, or convert any drive in order to continue; that decision belongs to the maintainer and is outside this procedure.

Before logging out of the usual user, connect the drive and check it without changing anything. Replace `<drive name>` with the name shown in the Finder:

```sh
ls /Volumes
diskutil info "/Volumes/<drive name>" | grep -i -E 'personality|bundle|owners|location|protocol|read-only'
ls -ld "/Volumes/<drive name>"
test -e "/Volumes/<drive name>/M11-v2-backup" && echo "M11-v2-backup exists" || echo "M11-v2-backup absent"
tmutil destinationinfo | grep -E 'Name|Kind|Mount Point'
tmutil status
```

None of these commands lists the drive's contents. The mount point must be exactly the expected name, without a suffix such as ` 1`. `Type (Bundle)` must be `apfs` or `hfs`; the device location must be external; and the volume must not be read-only. `M11-v2-backup` must be absent. The output of `ls -ld` shows whether the root of the volume is writable by the test user; if it is not, the Finder will ask for a password in Step 7, and the run stops there. Record the format that the system shows; it is entered in Step 7. Then eject the drive in the Finder.

If the drive is a Time Machine destination, as `tmutil destinationinfo` shows, its existing backups are not read or changed by this procedure. Time Machine may, however, start a backup while the drive is connected, and the Finder may then be unable to eject it in Step 11. The maintainer may set the Time Machine backup frequency to manual for the duration of the run and restore it afterwards; this changes a system setting and no stored backup, and it is the maintainer's choice. In any case, confirm with `tmutil status` that no backup is running (`Running = 0`) before connecting the drive in Step 7 and again before Step 11. If the Finder offers to stop a Time Machine backup in order to eject the drive, do not accept; let the wait of Step 11 expire and report the refusal.

The maintainer also needs the transferred archive `/Users/Shared/ilibrary-m11-qualification-v2.zip` and its checksum file `/Users/Shared/ilibrary-m11-qualification-v2.zip.sha256`.

## Step 1: Verify and Extract the Bundle

Log out of the usual user completely, log in as the existing test user, open Terminal, and run the following. The checksum is verified before extraction, and the command stops if the folder already exists. Music is not touched. The final command compares every file with the manifest.

```sh
cd /Users/Shared &&
shasum -a 256 -c ilibrary-m11-qualification-v2.zip.sha256 &&
cd ~ &&
test ! -e ilibrary-m11-qualification-v2 &&
unzip -q /Users/Shared/ilibrary-m11-qualification-v2.zip &&
cd ~/ilibrary-m11-qualification-v2 &&
mkdir results &&
set -o pipefail &&
sh collect.sh --check 2>&1 | tee results/bundle-check.log
```

The output ends with `bundle SHA-256 check: PASS`. If a check fails, if the folder exists, or if the command reports an error, do not extract over it or delete anything; report the output. Every later command is run from `~/ilibrary-m11-qualification-v2`, and every Terminal window needs `set -o pipefail` once, so that a failing command is not hidden by `tee`:

```sh
cd ~/ilibrary-m11-qualification-v2 && set -o pipefail
```

The bundle contains `bin/ilibrary`, `bin/M11Probe`, `staging/`, `catalog.json`, `collect.sh`, `m11_collect.py`, `PROCEDURE.md` (a copy of this document), and `manifest.json`. The manifest records the source commit and the SHA-256 of every other file.

## Step 2: Restore the Synthetic Dates

Archive extraction does not restore creation dates. The staging files carry the release dates of the catalog only after this step. Run the preview first and the change second; both affect only files in the bundle.

```sh
bin/ilibrary timestamps catalog.json staging --dry-run 2>&1 | tee results/staging-dates.log &&
bin/ilibrary timestamps catalog.json staging 2>&1 | tee -a results/staging-dates.log &&
bin/ilibrary validate catalog.json staging 2>&1 | tee results/validate-staging.log
```

Each date is read back by the command. The validation reports 12 matched files and exits with status 0.

## Step 3: Create a New Library

Create a new, empty library for this run. Do not reuse, empty, or open any library from M10 or the first M11 run.

1. Quit Music.
2. Hold the Option key while opening Music, and choose Create Library.
3. Save it in the Music folder of the test user's home, under the name `M11-qualification-v2`. If a library of this name exists, stop. The library `M11-qualification` of the first run stays where it is; Music only stops using it.
4. Open Settings, then Files, and confirm that the media location is inside this new library's folder. If it is already there, change nothing. If it is not, choose an empty `Media` folder inside the new library; do not move or change any earlier folder.
5. Confirm that the user is not signed in, that synchronization is off, and that Songs shows no tracks. Leave Music open.

The creation of a library is described in Apple's guide to multiple libraries, and the media location in the guide to Files settings. iCloud Music Library must be off. The procedure reduces the chance of cloud matching and detects its result; it does not prevent it.

## Step 4: Check the Environment

```sh
bin/ilibrary doctor 2>&1 | tee results/doctor.log
```

The expected output ends with `No problems found.` and names the new library's media folder, which must lie inside the `M11-qualification-v2` library folder. If the only finding is that the Automation permission cannot be determined, that is the state before the first library command; continue. If the media folder is not the new library's, and in particular if it lies inside `M11-qualification`, stop. Set the variable used by the following steps to the path that `doctor` printed after `media folder:`, then check it:

```sh
MEDIA="<the media folder path printed by doctor>"
test -d "$MEDIA" && ls -A "$MEDIA"
```

A new library's media folder should not yet hold a `Music` folder with files in it. If it does, stop.

## Step 5: Add the Synthetic Albums

Run the preview, read it, and then run the addition once. The preview reads the library and may cause macOS to ask whether Terminal may control Music; allow it.

```sh
bin/ilibrary add staging --order release --dry-run 2>&1 | tee results/add-dry-run.log
```

The preview lists the albums in release-date order, every planned move, and the checks, and states that nothing is changed. If it names a track that already exists in the library or refuses anything, stop. Otherwise run:

```sh
bin/ilibrary add staging --order release 2>&1 | tee results/add.log
```

Wait for the command to finish. It moves the files into the media folder album by album, adds each album, and confirms one track per file before the next album. The expected result is 3 albums and 12 tracks added, with exit status 0. In Music, Songs now shows 12 tracks. Do not edit, play, rename, or delete anything in Music. Do not rerun the command: a second run is refused by the duplicate check, and nothing is to be forced.

## Step 6: Record the Reader Comparison and the Strict Inventory

The probe is read-only. It reads the library once with the per-track reader, once with the bulk reader, and once with the snapshot reader that `rebuild prepare` uses. It compares the per-track and bulk readers field by field, checks the snapshot's identities and dates added, and writes one new report file. It refuses to run for any user that is not the test user, when an account is signed in, or when the output file exists.

```sh
bin/M11Probe readers --output results/readers.json 2>&1 | tee results/readers.log
```

Success is a report with the field comparison, the three durations, the cloud status values observed, and the smallest and largest age of the snapshot's dates added relative to the probe's clock; the exit status is 0. For tracks added in Step 5, the ages are expected to be small and positive; whether they are is assessed from the report. A comparison that differs or a fallback of the bulk reader to the per-track reader is a result to report, not a condition to repair; continue. If the probe instead prints `the probe stopped on an error`, stop here and go to Step 12; do not run the probe again. Otherwise record the strict export and the validation of the library files:

```sh
bin/ilibrary export "$MEDIA/Music" -o results/catalog-strict.json --strict 2>&1 | tee results/catalog-strict.log &&
bin/ilibrary validate catalog.json "$MEDIA/Music" 2>&1 | tee results/validate-library.log
```

The strict export exports 3 albums and 12 tracks and writes the catalog; the validation matches 12 files. Neither command touches Music.

## Step 7: Create the Backup With Finder

Quit Music; the next steps only copy files. Confirm with `tmutil status` that no Time Machine backup is running. Connect the external drive and confirm in the Finder that it is the drive checked before the run. In the Finder, create a new folder named `M11-v2-backup` at the root of the drive. Open the media folder (in the Finder, choose Go, then Go to Folder, and enter the value of `$MEDIA`), and drag its `Music` folder onto the new `M11-v2-backup` folder. Between two volumes, the Finder copies. Do not copy individual files, rename anything, open any other folder on the drive, or use any other tool. Wait for the copy to finish. If the Finder asks for a password or reports that the folder cannot be created or copied, stop.

Record how the backup was made and the format of the drive. Replace `Mac OS Extended (Case-sensitive, Journaled)` with the format exactly as the system showed it:

```sh
printf 'Backup made with a Finder copy of the media Music folder.\nDrive format shown by the system: %s\n' "Mac OS Extended (Case-sensitive, Journaled)" > results/backup-method.txt
BACKUP="/Volumes/<drive name>/M11-v2-backup/Music"
test -d "$BACKUP" && ls "$BACKUP"
```

The listing shows the same two artist folders as `ls "$MEDIA/Music"`. If the folder is absent or differs, stop. Do not open the backup in Music and do not edit it.

## Step 8: Create the Restoration and Workspace Directories

```sh
mkdir ~/m11-v2-restore ~/m11-v2-workspace
```

Both directories must be new; `mkdir` fails if either exists, and in that case you stop. The restoration directory must stay empty until the full run; do not open it in the Finder, which can create a hidden file in it. The evacuation directory named below, `~/m11-v2-evacuation`, is not created; the command only plans it in this version and writes nothing there.

## Step 9: Run the Preparation Preview

```sh
bin/ilibrary rebuild prepare catalog.json "$MEDIA/Music" --workspace ~/m11-v2-workspace --backup "$BACKUP" --restore-test ~/m11-v2-restore --staging ~/m11-v2-evacuation --confirm-separate-device --dry-run 2>&1 | tee results/prepare-dry-run.log
```

The command includes `--confirm-separate-device`, which states that the drive is a separate physical device; remove the option, and report why, if that statement is not true. The preview runs steps 1 to 4. The expected output prints the resolved locations; `Step 1 passed` with 12 files and 3 albums; `Step 2 passed` with 12 registrations mapped one-to-one; `Step 3 passed`; `Step 4 passed` with 12 files verified under the timestamp policy of the volume; the plan with capacity by volume, the addition and expected display orders, the backup facts, and the policy; and the final line `Dry run: steps 1 to 4 passed. Nothing was changed.` with status 0.

A refusal at any step is an observation to report, not a fault to correct. In particular, a refusal at Step 2 for a cloud status value, or at Step 4 for a date mismatch, is what this qualification exists to measure. Do not edit Music or the files to make it pass.

## Step 10: Run One Deliberate Negative Check

This step shows that the command refuses a backup that is not on a separate physical device. Make a second copy on the internal disk with the Finder: create a new folder `m11-v2-internal-backup` in the test user's home, and drag the media folder's `Music` folder into it. Then create two further new directories and run the preview against this internal copy. The subshell records the exit status.

```sh
mkdir ~/m11-v2-negative-workspace ~/m11-v2-negative-restore
( bin/ilibrary rebuild prepare catalog.json "$MEDIA/Music" --workspace ~/m11-v2-negative-workspace --backup ~/m11-v2-internal-backup/Music --restore-test ~/m11-v2-negative-restore --staging ~/m11-v2-evacuation --confirm-separate-device --dry-run; echo "exit status: $?" ) 2>&1 | tee results/negative-internal.log
```

The expected result is a refusal: status 1 and a reason of the form `the backup shares the physical disk ... with the ...`, followed by `rebuild prepare stopped at step 3` or `step 4` and a statement that nothing was changed. The statement `--confirm-separate-device` is given deliberately, so that the refusal can only come from the device information and not from the missing confirmation. If the command instead passes, report that result without comment; it means that the device signal did not detect the shared disk. Leave the internal copy and both directories in place.

## Step 11: Run the Full Preparation and Eject the Drive

Keep the external drive connected, and confirm with `tmutil status` that no Time Machine backup is running. Run the full command once.

```sh
bin/ilibrary rebuild prepare catalog.json "$MEDIA/Music" --workspace ~/m11-v2-workspace --backup "$BACKUP" --restore-test ~/m11-v2-restore --staging ~/m11-v2-evacuation --confirm-separate-device 2>&1 | tee results/prepare.log
```

The command repeats steps 1 to 4 and prints the plan with the statement of what it will write: 12 restored files in `~/m11-v2-restore` and one recovery record in `~/m11-v2-workspace`. Step 5 copies the 12 files from the backup into the restoration directory, sets their dates, and verifies bytes, paths, and dates. The command then prints `Eject the backup volume now` with the volume name and UUID, and waits up to 600 seconds. In the Finder, eject the drive by choosing the eject button beside it in the sidebar. iLibrary does not unmount anything. Do not unplug the drive before it has been ejected, and do not reconnect it afterwards. If the Finder offers to stop a Time Machine backup, decline.

The expected result is `Step 5 passed`, `Step 6 passed: the backup volume is no longer mounted`, `Step 7 passed`, the line `Prepared: stage prepared, 12 files, 3 albums`, and status 0. If the volume is not ejected within the wait, the command stops at Step 6 with a refusal; report it and do not run the command again in the same workspace, because it never overwrites a record. If a step fails, the last line states what was changed: nothing, or only the restored files, which are kept.

Then read the recovery record without Music or the drive:

```sh
bin/ilibrary rebuild status --workspace ~/m11-v2-workspace 2>&1 | tee results/status.log
```

The expected output reports the stage `prepared`, 12 files, the backup and restoration results, and that the next required action is to keep the record and the backup. The record is private and is never sent.

## Interruption Precautions

Do not press Control-C during Step 5, during the restoration of Step 11, or during the probe unless the output has not changed for ten minutes. An interrupted `add` is resumed by the next run of the same command from the same staging folder; do not run it with other options and do not move files by hand. An interrupted `rebuild prepare` leaves restored files in the restoration directory, which are kept; do not rerun it in the same workspace or restoration directory, and report the last output. If the Terminal is closed accidentally, do the same.

## What Not to Do

Do not remove a registration from Music by hand or by command. Do not edit tracks, albums, or settings in Music after Step 3, and do not change the album name of any track, because that triggers folder reorganization. Do not reuse, empty, or open any M10 library or the first run's `M11-qualification` library. Do not reformat, erase, repartition, or rename a drive, and do not open, move, or change any other folder on it, including Time Machine backups. Do not copy the media folder with any tool other than the Finder, since the Finder's date behavior is part of the measurement. Do not delete the backup, the restoration directory, the workspace, the internal copy, the bundle, or anything from the first run before the report has been assessed. Do not sign in to an Apple Account, and do not run anything in the usual user's account other than the read-only drive checks above.

## Step 12: Produce One Report

After the run, whether it passed, stopped, or was interrupted, run the following once as the test user. It combines the saved logs and the probe report into one new file. It reads no Music state and writes nothing else. A step that was not run is recorded as `NOT RUN`.

```sh
sh collect.sh /Users/Shared/ilibrary-m11-qualification-v2-report.txt
```

The command refuses to overwrite an existing report, and the first run's report keeps its own name. The report starts with the source commit of the manifest and records the result of the bundle check and, when the archive is still in `/Users/Shared`, of its checksum. In the report, the home directory of the test user is replaced by `~`, every `/Volumes/<name>` prefix by `/Volumes/BACKUP`, and every persistent identifier of 16 hexadecimal digits by `<id>`. Over-redaction is possible: a volume name is replaced up to the next slash, quotation mark, or end of line. Read the report once before sending it.

Return to the usual user and send only this sentence:

> Please assess the M11 version 2 backup and inventory qualification: /Users/Shared/ilibrary-m11-qualification-v2-report.txt

Do not send the recovery record, the logs, the probe's JSON, the audio files, or the disk. Keep them in the test user. If the run stopped before a report could be made, send the step number and the last output instead.

## Evidence Limits

The report is a record of one run. The live equivalence, the cloud status values, the snapshot reader's dates added, the Finder's preservation of dates on the external drive, the device-independence signals of a real external drive, and the disconnection wait are measured only by this run, and each is unknown until the report is assessed. The Finder copy and the ejection are actions of the maintainer; their correct execution is not independently verified except through the recorded outputs. The dates of the staging files are restored in Step 2 and are not preserved by the archive. The assessment decides whether M11 has passed.

The preparation script is `sh scripts/validation/prepare-m11-qualification.sh --prepare` (`--dry-run` creates nothing). The redaction test is `cd scripts/validation && PYTHONDONTWRITEBYTECODE=1 python3 -m unittest test_m11_collect`, which needs no Music.
