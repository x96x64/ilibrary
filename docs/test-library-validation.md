# Test Library Validation

## Purpose

この手順は、実装した `add`・`check`・`doctor` を別の macOS ユーザーで確認するためのものです。普段の音楽や Apple Account は使いません。前回の測定は Music の動きを調べたもので、今回のコマンドの動作確認とは別です。

M7 までの実装と文書整備は、この確認を待たずに進められます。確認結果が届くまでは、M5 の実ライブラリ検証ゲートを未完了と記録します。ここでいうライブラリは検証用ユーザーの合成音声だけです。

## Step 1: Select a Test User

次のどちらかを選びます。**前回の検証用ユーザーが残っていれば、その再利用を推奨します。**

- **再利用（推奨）**：Apple Account にサインインしておらず、前回の合成音声 5 曲だけがあるユーザーを使います。アカウント名は `ilibrarytest` または `ilibrary-test` で始まる必要があります。
- **新しく作成**：条件が合わない場合は、普段のユーザーで「システム設定」→「ユーザとグループ」→「ユーザを追加」を開きます。種類は「通常」、名前は自由、アカウント名は `ilibrarytest2` にします。任意のパスワードを設定し、作成します。パスワードを報告する必要はありません。

普段のユーザーからログアウトし、検証用ユーザーでログインします。Apple Account の案内はスキップします。普段の音楽や Music ライブラリをコピーしないでください。

## Step 2: Prepare Music and Terminal

1. 検証用ユーザーで Music を一度開きます。サインインやサブスクリプションの案内は進めません。
2. 新規ユーザーなら曲が 0 件であること、再利用なら前回の `iLibrary Probe Artist` の 5 曲だけであることを確認します。それ以外があれば、この手順を進めずに状況だけ報告します。
3. 「ターミナル」を開きます。以下はすべて、この検証用ユーザーのターミナルで実行します。

初めて取得する場合：

```sh
git clone https://github.com/x96x64/ilibrary.git
cd ilibrary
```

前回のフォルダが残っている場合：

```sh
cd ~/ilibrary
git switch main
git pull --ff-only
```

開発用ツールのインストール画面が出た場合は、画面の案内に従います。Git が変更の競合を報告した場合は、削除や上書きをせず、そのエラーを報告してください。

## Step 3: Run the Validation

```sh
scripts/validation/library-commands.sh --run-live
```

1. 最初の説明を読み、検証用ユーザーであることを確認して `TEST` と入力し、Return を押します。
2. 音声の準備とプログラムのビルドには数分かかる場合があります。
3. ターミナルから Music を操作してよいか聞かれたら許可します。今回の確認で必要な許可です。
4. 合成音声 3 曲が 2 アルバムとして追加されます。重複の拒否、ファイルの日時、ファイルの一時移動を使った検査を行います。一時移動したファイルは戻します。ライブラリの曲は削除しません。
5. 最後に、デスクトップに `ilibrary-command-results.txt` が作成されます。

検査は途中で止めずに完了まで待ってください。エラーで止まった場合は、同じコマンドを繰り返したり、検証用ユーザーを削除したりせず、次の方法で報告します。前回の結果がある場合、スクリプトは上書きせず停止します。

## Step 4: Report the Result

デスクトップの `ilibrary-command-results.txt` をテキストエディットで開き、内容をそのまま会話に貼り付けてください。作業したコミット、OS の版、検査の成功・失敗が含まれます。曲の識別子、個人のパス、アカウント情報は含めません。

結果ファイルが作られなかった場合は、次だけを報告してください。

```text
別ユーザーでの確認が途中で止まりました。
止まった手順：Step 2 または Step 3
画面の最後のエラー：ここに貼り付け（個人名やパスがあれば伏せる）
Music の操作許可：許可した／拒否した／表示されなかった
```

`artifacts/` 内の詳しいログや `.ilibrary-add.json` は貼り付けないでください。検証用であってもユーザーのパスや曲の識別子を含みます。

## Step 5: Return to the Usual User

検証用ユーザーからログアウトして、普段のユーザーに戻ります。結果を確認し終えるまで検証用ユーザーとファイルを残しておけば、失敗の原因を調べられます。普段の Music では、この検証を実行しません。

## Preparation Without Music

開発中に音声の生成とファイル検査だけを確認する場合は、次を使います。このモードは Music を開かず、ライブラリも読みません。

```sh
scripts/validation/library-commands.sh --prepare-only
```

## Recommended Models and Effort

結果の確認と、必要な修正の推奨：Claude Code は Claude Opus 5.5・xhigh、Codex は GPT-6-Astra・xhigh。Music の追加処理の検証を含むため、ロードマップの M5 に合わせます。
